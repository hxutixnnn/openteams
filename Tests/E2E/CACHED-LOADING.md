# Cached-conversation loading

This change moves initial cached-message conversion from MainActor to a private serial actor. Decoded raw history is retained before conversion suspends so concurrent sends and refreshes merge into it. Publication checks account generation, cancellation and unchanged message values; prepared results never overwrite a newer history. Cancellation leaves raw history available for a retry, without publishing partial rendered rows. Changed participant metadata uses the existing synchronous renderer. A send that finishes before raw history is available reads the account-scoped cache instead of creating an empty replacement, then rechecks generation and current history. Cache files and account paths are unchanged.

The timeline shows loading during cached conversion as well as network reads. Concurrent initial calls are counted separately, so one cancellation cannot clear another call's loading state. Mutation paths retain synchronous rendering: a send or refresh during conversion can still do rich conversion on MainActor. This PR does not claim that every overlapping mutation is free of UI-thread blocking. The worker checks cancellation before each message and creates no per-message tasks.

It checks all original rich messages, 2,001/2,000 final rows, paging token, loading-state cleanup, targeting and sent/retained drafts using intercepted HTTP only. Its refresh returns a known old row so the token assertion is distinct from the existing empty-page refresh behavior.

The DEBUG callback reports cache-read/decode elapsed time, conversion execution time and synchronous MainActor publication time. Cache elapsed time includes the actor hop/queue, file I/O, JSON decoding and retaining raw history on MainActor. Conversion excludes worker queue time. Publication includes message validation, reconciliation and snapshot/array installation; it excludes SwiftUI layout/drawing. Total load time is measured through completion of the offline public load operation and includes all hops and queueing. MainActor conversion/publication spans measure those specific synchronous regions; they are not a whole-process trace, native frame metric or first-visible-frame measurement. No private content or account identifiers are logged by these spans. The callback and clocks are excluded from release builds.

## Controlled DEBUG loading overlap

`--enable-cached-load-hold` opts the isolated native fixture into a cooperative gate. Prepare separate roots with `--cached-history-count 2000 --enable-cached-load-hold`, adding `--allow-fictional-send` only for the successful-send root. The flag is false by default and recorded as `OpenTeamsCachedLoadHoldEnabled` in the signed plist and `cached_load_hold_enabled` in the immutable manifest. `--skip-build` reuses an already verified debug build; use it only when its source hashes match the clean review head. No fixture is launched by preparation.

The gate starts Unarmed. It suspends the next cold cached preparation after the real raw history snapshot is retained, before worker conversion or publication. The real cached-load count remains active. The await leaves MainActor available. Conversion timing excludes the held interval. Production Send, editor, history reconciliation and generation checks remain unchanged. DEBUG code rechecks generation, account revision and cancellation after the gate; the existing post-worker guards still apply. Release builds contain neither the gate nor its API or trace. A controlled interleaving does not measure natural loading duration, latency or FPS.
